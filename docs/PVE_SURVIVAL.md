# PvE 생존 듀얼 · 1.6.2

## 적용 범위

**Play → Duel**의 CPU 연습 및 온라인 랜덤/친구방 모두 같은 `survival` 1대1 엔진을 사용합니다. 온라인은 서버가 시간·활성도·증폭 턴·OVF·보스·승패를 결정합니다. 새 친구방은 최대2인입니다. 이전 `classic`/`clash` API는 호환용으로 유지하며 기존 싱글플레이는 그대로입니다.

GitHub Pages는 프론트엔드입니다. 실제 인터넷 PvP에는 이 버전의 백엔드를 별도로 실행하고 API 주소를 연결해야 합니다. 공개 서버의 실사용 대전 검증은 수행하지 않았습니다.

## 공유 패턴과 진행

같은 매치 시드로 일반 적의 종류/방향/생성/도착 계획을 한 번 생성하여 양쪽에 복제합니다. CPU가 직접 바이러스를 쏘거나 사람이 공격 방향을 골라 탄환을 만드는 방식이 아닙니다. 초기 패턴은 같고, 실제 파생 위협은 각자의 처치/실패에 따라 달라집니다. 트로이 숙주의 패링 여부, 웜 카운트 등은 개인별로 처리합니다. 같은 숙주를 패링하면 탈출 방향도 같습니다. 패링 가능한 파생 공격도 순차 도착 간격을 예약합니다. 숙주를 놓친 트로이의 추가 침투는 코어에서 튕겼다가 돌아오는 방어 불가8%p 후속 피해입니다.

3분 동안 진행 배율을 선형으로 높이고 이후 상한을 유지합니다.

| 항목 | 시작: 보통 | 180초 이후: 익스트림 |
| --- | --- | --- |
| 일반 이동 배율 | 1.20 | 1.75 |
| 생성/예약 간격 | 1305ms | 330ms |
| 방어 판정 | ±300ms | ±200ms |
| 정밀 판정 | ±85ms | ±55ms |

바이러스는 처음부터, DDoS는 3번째 이후, 트로이 숙주는 8번째 이후, 웜은 15번째 이후, 랜섬웨어는 25번째 이후, 피싱은 40번째 이후 패턴에서 확률적으로 등장합니다. 적 피해는 기본 무한 모드 기준의 종류별 피해입니다. 판정선을 지나도 코어에 닿기 전까지 이동하며, 실제 코어 접촉 때 피해를 받습니다. 짧은 터치는 누른 시각으로 판정합니다.

## 활성도

취약률과 별도인 **0~100%** 자원입니다. 시작0, 자연 충전 없음, 재도전 시 초기화합니다. 방어 가능한 적 제거에 성공하면 다음 기본량을 얻습니다.

| 위협 | 기본 활성도 |
| --- | --- |
| 바이러스 | 3 |
| DDoS | 4 |
| 트로이 | 6 |
| 컴퓨터 웜 | 8 |
| 랜섬웨어 | 4 |
| 피싱 본체 | 7 |
| 보스의 유효 패링 | 0 (활성도 획득 없음) |

일반 적의 실제 획득량은 **(기본량×정밀 배율 + 아래 연속 보너스)×0.5**이며 0.1 단위로 반올림합니다. 이전 버전 대비 절반입니다. 정밀 배율은1.5, 비정밀은1입니다. 연속 패링은 5회마다 +0.5, 최대+2. 연속 정밀은 3회마다 +0.5, 최대+3을 추가합니다. 비정밀 방어는 정밀 연속만 끊고, 피격/헛방어는 두 연속 모두 끊습니다. 보너스가 있어도 활성도 절대 상한은100%입니다. 정밀 패링의 기본 취약률 회복4%p(웜20%p)도 유지합니다.

Space, 활성도 버튼, 경기장 안 스와이프는 **현재 보유량과 (10 + OVF) 중 작은 양**을 자동 사용합니다. Shift+방향도 보조 단축키로 지원합니다. 발동 대기시간은350ms이며 키 자동 반복은 무시합니다. 별도 양 선택 UI는 없습니다. 새 모드의 스와이프는 28px 이상이면 방향과 시작 라인에 관계없이 사용할 수 있습니다.

- 내 증폭이0: 소모량 전부를 상대의 대기 증폭에 더합니다.
- 내 증폭이 양수: 소모량으로 먼저 상쇄합니다. 남는 소모량은 절반만 상대 증폭에 더합니다.
- 예: 상대 증폭10에 내 활성도6으로 대응 → 내 증폭4 잔여.
- 예: 내 증폭6에 활성도10 사용 → 내 증폭0, 상대 증폭+2.
- 예: 내 증폭0에 활성도10 사용 → 상대 증폭+10.

증폭은 비율 곱셈이 아닌 **추가 피해 퍼센트포인트**입니다. 각 공격은 별도 증폭 턴으로 저장됩니다. 10, 7로 두 번 공격하면 첫 코어 피격 +10, 다음 코어 피격 +7입니다. 코어 피격은 맨 앞 턴만 소비하며 보스 코어 피해도 같습니다. 경감은 오래된 턴부터 차례대로 줄이며 턴을 넘어 계속 적용합니다. 예: 바이러스14 + 증폭10 =24%p. 헛방어나 보스 숫자 순서 오입력은 코어 접촉이 아니므로 증폭을 소모하지 않습니다. 취약률 텍스트는 소수 첫째 자리에서 반올림해 정수로 표시하며 원래 수치와 바 길이는 보존합니다. 증폭 자체에 임의의100 상한은 두지 않습니다.

## OVF · 일회성 확장

연속 정밀 3회째부터 매 정밀 패링에 +2, 최대 +20입니다. 보스의 유효 정밀 패링도 OVF에는 기여하지만 활성도는 주지 않습니다. 연속이 끊기면 성장은 멈추며, 이미 저장된 OVF는 다음 활성도 사용까지 유지합니다.

활성도 사용 시 소모 한도가 10+OVF로 늘어납니다. 내 증폭이 있으면 실제 소모 활성도+OVF만큼 경감하며, OVF 무료 경감분은 반사하지 않습니다. 반사량은 여전히 실제 소모 활성도에서 기존 증폭 총량을 뺀 양의 절반입니다. 성공한 활성도 사용 한 번에 OVF와 정밀 연속 기록을 초기화합니다. 에너지 부족·대기·쿨다운 등 거절된 입력은 OVF를 소비하지 않습니다.

OVF가 0이면 숨기며 OVF가 양수일 때 경기장 왼쪽 위에 `OVF +N%` 텍스트를 표시하고 상승할 때 짧은 확대·이동과 상승 음정 효과음을 적용합니다. 음소거와 모션 감소 설정을 따릅니다.

## 보스 웨이브

경기 시작 후60/120/180…초에 진입을 시도합니다. 이미 진행 중인 보스 웨이브와 겹치지는 않습니다.

1. 새 일반 생성을 멈추고 아직 화면에 나오지 않은 예약 적은 취소합니다.
2. 각 플레이어는 자기 필드에 남은 적을 처리합니다. 대기 웜은 돌진시켜 진행이 막히지 않게 합니다.
3. 필드가 비면 그 플레이어에게 경고 후 보스가 등장합니다. 상대가 아직 정리 중이어도 독립 진입합니다.
4. 보스는 등록된 종류 중 무작위로 하나를 고르고 양쪽이 같은 종류·시드를 사용합니다.
5. 먼저 완료하면 대기하며 공격/활성도 입력도 잠깁니다. 살아 있는 전원이 끝나면 일반 생성을 재개합니다.
6. 웨이브 시작부터45초가 지나면 미완료자에게 남은 시도횟수×20%p(최소20)의 코어 피해를 적용하고 남은 필드와 보스를 정리합니다. 진행 중인 보스가 없으면 최소20입니다. 이 피해도 증폭을 소비합니다.

보스 중 탈락하면 일반 듀얼의 승패 규칙이 우선합니다. 웨이브 종료 직후1초 뒤부터 패턴을 재개하고, 다음 미래의 분 단위에 다시 보스를 시도합니다. 보스 패턴의 원래 회복·분열·숫자 순서는 유지합니다. 보스 패링은 활성도를 충전하지 않으며, 보스를 실제 처치하면 대기 증폭을 총30%p 경감합니다. 처치 보상은 각자 한 번만 적용하며 실패·도주·시간초과는 보상하지 않습니다. 웨이브 시간·패턴 강화 시간은 일시정지 없는 PvE 경기 시계를 기준으로 합니다.

## CPU와 화면

입문/대등/숙련의 방어 시도 확률은75/90/98%, 예정 시각 오차는±200/80/45ms입니다. 새 모드에서는 CPU도 일반 적을 패링해 같은 활성도를 얻습니다. 자신의 증폭이 있으면 상쇄를 시도하고, 평소에는10 이상 모이면 공격합니다. 기존처럼 수동 탄환이나 능력을 생성하지 않습니다.

각 플레이어 경기장 옆에 굵은 세로 활성도 바(10% 단위 분할), 아래에 취약률 바를 표시합니다. 현재 취약률 뒤에 증폭 턴을 빨강/노랑 교대로 이어서 예고하며 다음 피격 순서를 텍스트로도 표시합니다. 100% 바를 넘는 증폭도 아래 텍스트에는 남습니다. 능력 카드 패널은 새 모드에서 비활성입니다.

## 구현 경계·검증

`duel-survival.js`가 새 순수 규칙 엔진입니다. `duel-engine.js`는 `mode='survival'`일 때만 이 엔진에 위임합니다. `classic`/`clash`는 기존 PvP 코드입니다. `duel.js`의 CPU 연습과 신규 온라인 방/매칭이 모두 새 모드를 선택합니다.

기존 Clash/PvP 화면 회귀 검사는 명시적 legacy fixture를 사용합니다. 새 테스트는 실제 CPU 연습 진입점과 별도 생존 엔진을 검증합니다. 공유 패턴/시드, 활성도 상한·연속 보너스, 상쇄 예시, 코어 접촉/단발 증폭, 개인별 보스 진입·대기·타임아웃, 두 웨이브의 완료·재개를 검사합니다. 브라우저에서는 키보드 Space와 터치·스와이프 경로, 상태 복원 및 재도전을 확인합니다.

실제로 나타난 위협과 자기 보스는 기존 발견 도감에도 기록합니다. 숨은 트로이 숙주 표시는 공개하지 않으며, 추가 침투가 드러난 경우 트로이 발견으로 처리합니다.

## 1.6.2 피드백·온라인 적용

공격 이벤트마다 공격자와 대상 경기장 모두 소모량에 비례해 흔들립니다(0.8 + 소모량×0.2, 최대7 SVG 단위). 모션 감소 시 제외합니다. OVF 색상은 0 녹색, 4 주황, 8 빨강, 11 보라, 14 파랑, 17 하늘, 20 이상 검정을 기준으로 RGB 보간하며 검정은 밝은 얇은 외곽선으로 대비를 유지합니다.

온라인 새 방/매칭의 모드는 `survival`입니다. 백엔드가 같은 순수 엔진을 import하며 인증·입력 중복 차단·스트림·이탈·재대전 경로를 사용합니다. 서버 epoch 시각으로 생성할 때 시작 3초 전부터 진행하여 1970년부터 따라잡는 루프를 방지합니다. 기존 Clash 능력/8인 테스트는 호환 API 회귀 검사입니다.

검증: 전체190개 테스트 통과. 두 개의 독립 Chromium 화면에서 실제 로컬 HTTP 방 생성·참가·준비·SSE 수신과 같은 패턴·새 HUD 진입을 확인했습니다. 실제 외부 호스팅 서버나 서로 다른 인터넷 기기 간 대전은 별도 검증이 필요합니다.
